# STC 夜间真实子集研究（2026-10-16）

## 状态与边界

目标是完整 VAL4369、相同 full-grid 口径同时超过 mIoU 18.97 / IoU 28.77。
**目前没有完整人口的候选结果，因此目标尚未验证。不能将64窗提升加到旧全集分数上。**

用户提供的57.9MB小包位于工作区根目录 `stc_overnight_bundle.zip`，包括精确 reference64
（64个不同 VAL 场景，每场景1窗）及32个原 TRAIN 场景的窗口；两套纯 GT 训练来源的主体：
`dense_epoch2` 与 `clean1000`。按 manifest 校验读取的标签/权重 SHA，无原始相机/LiDAR。
包内 GT lidar mask 仅供 GT 历史读取，STC 分支禁止读取它。

所有下表均为同64窗，GT未来ego条件，四历史/六未来，1/2/3s全网格标准 mIoU/IoU。
Moving 未导出相应标注，因此没有新的 Moving 结论。这里也没有新的 FPS 结论。
RTX3050 Laptop 4GiB、Torch2.6；原服务器Torch2.7。H1分组推理仍产生全部六帧。

## 最有信号的冻结时序候选

固定原最近两帧匹配，不因旧历史产生新的末帧速度。至少三帧关联时，用历史中心/真实时间
做恒速线性拟合，速度取 `0.5 * 原两帧速度 + 0.5 * 多帧拟合速度`。
所有依赖速度的未来 KTA / anchor / Strong 背景一致更新，STWM原学习残差继续保留。
历史 source patch / registration 有效性规则不改。clean1000 原独立 registration 仍保留；
它的额外四帧关联仅用于独立速度估计，不能误称已经正式融合了全部旧 source 路径。

特征池化给历史 `[t-1.5,t-1,t-.5,t0]` 固定权重 `[1/8,1/4,1/2,1]`。
这是模型行为变化而非无损提速，不继承原 FPS。

## 后验分布校准

借鉴 [AdaMatch](https://arxiv.org/abs/2106.04732) 的相对分布对齐思想，
不是复现其完整算法。用原 TRAIN32 的 **GT历史预测后验** 作源统计，
用 reference64 **未标注 STC 预测后验** 作目标统计；拟合时不读取目标 GT 标签。
这是 transductive calibration，不称 target-domain-information-free。

clean1000 源预测 occupied posterior 均值 `.056435`，目标 `.045033`，
数据推导的二元 occupied/free log-odds 偏置 `.237695`；没有系数扫描。

### 组合的收益边界（仅同64场景开发集）

新增 `boundary_audit.py` 只读取已有整数confusion，不预测/训练、不读新GT文件。
clean组合在1/2/3s的mIoU增量分别 `.233945/.475286/.482716`，
IoU增量 `.364573/.367299/.483626`；64场景中50个mIoU、53个IoU为正。
依次去掉任意一个场景，聚合增量仍为正：mIoU `.338347--.436251`，
IoU `.363220--.419766`。这些是反复开发后的条件描述，**不是独立显著性检验**。

累计占据TP从2,440,309到2,515,462，FN从3,675,822到3,600,669，
但FP也从2,492,017到2,632,146。因此不能称“普遍抑制感知噪声”：
这组组合主要用更多占据预测换取召回，精度有所牺牲，最终两项IoU变好。
不同场景/前端的收益仍可能改变，不能保证超过全集目标。

另测“接受的历史ICP逆变换回溯同一t0锚点”，代替残缺点云的原始质心测量，
保持原最近两帧身份、半幅速度收缩及age memory：`18.462027 / 28.515899`，
而原raw-centroid LS组合为 `18.456140 / 28.514926`。
576/577个可多帧拟合source实际用到了此配准测量，说明不是因为几乎没有启用而持平；
额外增益仅 `.005887/.000973`，不足以采用，不再叠进推荐组合。
新代码隔离在 `registered_velocity.py`；用于已交付全集任务的
`verify_all.py/replay.py/bundle.py/calibration.py` 字节未改，避免破坏正在运行或待恢复的任务。
本轮新增检查后 `14 passed in 6.72s`；replay实际SHA与前次完整64入口contract完全相同，
不是只靠git的换行归一化判断兼容。已结束所有本地进程，没有可代替全集报告的后台任务。

## 定位实验和没有采用的方向

- **GT历史特征 oracle**：保持STC几何、原STC运动/HQ、注册/特征点位置，只给Refiner换
  GT历史编码后lift的特征。mIoU/IoU变为 `21.149651 / 35.636938`，较原dense约
  `+2.928460 / +7.480455`。它用到了GT历史，严格不是可报告的STC成绩。
  它支持继续研究历史特征质量，不证明能学到这整个上界。
- 两独立模型等权概率融合 `18.242553 / 28.337945`，没有超过两基线的全部指标。
- 四镜像概率融合 `18.256666 / 28.069774`；平移相位融合、简单XY概率平滑无实质收益。
  镜像/平移均同步共轭历史和未来ego位姿，并恢复输出位置，不是误用坐标来对齐GT。
- 只在原占据位置减半最终先验 `18.110183 / 27.917142`，不采用；全图c=.5的旧失败也不重启。
- 双向历史多数先验 `18.048284 / 27.882330`，旧free会抹掉当前正确占据；
  只给有旧历史支持的当前free加入软证据也只有小收益。
- 仅t0记忆、仅静态t0、完整LS速度、Wiener速度、中心平滑、均匀importance、距离池化等
  机制控制均保留结果，没有自动替换固定半幅速度＋衰减方案。
- 原 TRAIN32 模拟噪声去噪器，真实STC当前帧从 `24.197062 / 32.676098`
  降为 `22.564066 / 31.154887`；直接encoder特征蒸馏未来分数亦下降。
- 另做32真实VAL场景历史GT特征监督、另32场景留出的小adapter研究。
  留出原模型 `18.157465 / 29.174786`，adapter `17.985128 / 28.727962`，失败。
  它用了VAL历史GT作监督，严格单列，**不能用于全集4369正式成绩**。

## 已完成的学习对照

`occupancy_head.py` 冻结原 clean1000，仅训练1025参数的有界占据校准头：
原 memory16 + coarse prior18 -> tiny CNN -> `beta in [-2,2]`，
给所有非free类加同一beta，free类不变；语义类内排序由原模型决定。
零初始化严格保持原始输出；无ADD/REMOVE动作阈值。

只用原TRAIN32，clean与固定模拟污染各训500步、同初始化/顺序/Adam/整周期余弦；
每步完整六时距CE+Lovasz，主体/ego/motion/existence均不优化。VAL不参与训练。
这是针对低维先验可信度/占据赔率的独立小研究，结果已经完成：
clean头 `18.118273 / 28.342770`，corrupted头 `17.978144 / 28.018265`，
原模型 `18.110905 / 28.355717`。没有同时改善两项，不采用，不扩大。
新cache只存其冻结float32前向及TRAIN标签，约24.49GiB，不覆写旧cache。

虚拟视点用名义高度，**不是实际相机/LiDAR标定**，不能将这个结果解释为
对真实传感器ray casting的完整评估。它显示这版过滤会误删正确遮挡占据。

另检查了四历史的二元latent-observer EM：只从已配准STC历史估计四帧的观测
敏感度/误报率，50固定迭代、无GT或旧VAL噪声拟合参数、无系数扫描，再与当前
静态先验等权混合。clean1000 `18.124416 / 28.423725`，较原版仅
`+0.013512 / +0.068008`，未超过固定历史支持，不加入推荐组合。
思想参考 [Dawid & Skene 原文](https://crowdsourcing-class.org/readings/downloads/ml/EM.pdf)
中的潜在真值/观测错误率估计；本文所需的条件独立性在STC时序错误中并不成立，
因此不能把该模型当作可靠的“真噪声恢复器”。独立合成噪声下恢复参数的单测通过，
只说明实现符合该假设，不证明真实时序误差能这样拟合。
