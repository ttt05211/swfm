## 2. Why V19 exists

The completed 3--6 s zero-shot rollout exposed a scene-state maintenance
limitation.

Formal open-loop 4/5/6 s mIoU:
28.835 / 25.412 / 22.945.

Teacher-forced GT-history 4/5/6 s mIoU:
51.490 / 41.711 / 35.965.

Thus the frozen relative-horizon predictor still works from a clean scene
state; the long-range limitation is maintaining a valid state without new
observations.

The method story is:

Remember what has been observed
-> transport content with a reliable ancestor
-> generate only content without a reliable ancestor
-> promote stable generated content back into memory.

## 3. V19 method contract

### 3.1 Dynamic source path

Current or re-detected sources remain authoritative and use the exact frozen
Clean-E14 path.

SourceMemory stores lifecycle information:
identity, class, canonical geometry, historical centres, velocity, confidence,
provenance and age since real observation.

Memory does not replace detection.

At a block boundary:

    generated/current occupancy
      -> Strong redetection
      -> SourceMemory reconciliation
           matched detected     -> exact V18
           new detected         -> exact V18 + fresh memory identity
           unmatched memory     -> low-confidence add-only recovery

### 3.2 Static memory

Only Occ3D mask_lidar-observed non-motion-capable geometry is remembered.

Rules:

- dynamic observations never enter static memory;
- dynamic occlusion does not erase static memory;
- newer genuinely observed free evidence clears stale static occupancy;
- newer valid static observation wins;
- future rendering is deterministic world-to-future-ego geometry;
- composition is add-only.

### 3.3 Innovation

Innovation is not "whatever V18 gets wrong".

It is future occupancy with no reliable historical ancestor, principally:

- future-born dynamic content;
- never-seen static content;
- source shape innovation.

History is explicitly warped into each future ego frame before the innovation
network. Deterministic ego geometry is not learned.

## 5. Important implementation invariants

1. Current/re-detected source order is the original Strong order.
2. Matched sources are never rewritten by memory.
3. Memory-only recovery runs separately and composes only into free voxels.
4. Source state separates:
   - detected_at_anchor;
   - age_since_real_observation.
5. Memory adapters are gate-isolated from detected sources.
6. New memory heads are zero initialized.
7. Static memory uses mask_lidar, not semantics!=free as visibility.
8. Innovation is protected add-only.
9. Future GT is diagnostic/training supervision only, never prediction input.
10. Stable track IDs survive reconciliation and can be reused in later blocks.

### 10.3 New decomposition protocol v2

The next and final pre-training diagnostic is:

p0_f9_v19_innovation_decomposition_perfect_add_v2

It resolves a conceptual error in the old dynamic_other bucket. For a future GT
dynamic component linked to an already represented t0 source, the diagnostic
now asks whether exact GT-motion transport of the observed t0 source geometry
covers each missing voxel:

- covered -> current_source_transportable_miss
  (known ancestor; V18 motion/yaw/composition miss; NOT innovation);
- not covered -> source_shape_innovation
  (the future component contains geometry absent from the transported observed
  source; valid innovation candidate).

Future dynamic GT occupancy is attributed through min-size-1 same-class
connected components, then independently linked to GT instance identity.
Many occupancy fragments are allowed to map to one instance because this is a
diagnostic ancestry assignment, not deployment tracking.

### 11.1 What decomposition v2 changes

Protocol:

    p0_f9_v19_innovation_decomposition_perfect_add_v2

Future dynamic GT occupancy is now decomposed through same-class connected
components with `min_component_voxels=1`, so tiny/fragmented dynamic GT is not
discarded by the normal Strong minimum-size threshold.

Diagnostic component-to-instance assignment is many-to-one: several future
occupancy fragments may map to the same GT instance. This is diagnostic
ancestry attribution, not deployment tracking.

For a future component linked to an already represented t0 source, exact
GT-motion transport of the actually observed t0 source geometry splits misses:

    current_source_transportable_miss
        -> known ancestor; motion/yaw/composition/model miss; NOT innovation

    source_shape_innovation
        -> future visible geometry not covered by transported observed shape;
           valid innovation candidate

Group-level perfect-add oracles are now reported for:

    core_innovation
    memory_addressable
    known_ancestor_model_miss
    ambiguous

The diagnostic also prints `DYNAMIC AMBIGUOUS AUDIT`, including unresolved
voxel/component counts, moving overlap, nearest same-class annotation-distance
bins, per-class ambiguous voxel counts, and moving fraction.

### 11.4 Story that must be preserved

The paper story is NOT "V18 has errors, so add memory and a residual CNN."

It is:

    1. Observed dynamic sources have reliable ancestors -> transport them.
    2. Previously observed geometry should be remembered -> render memory.
    3. Content without a reliable ancestor is genuine innovation -> generate it.

For long rollout, detection is authoritative when available; Source Memory is
a sparse lifecycle mechanism, Static Memory preserves observed geometry, and
Innovation creates genuinely new content that may later become known state.

Do not repeat without a new reason:

- pure persistent source memory replacing redetection (hurts Moving);
- naive dormant KTA as a headline module (slightly negative smoke);
- all-V18-false-negatives-as-innovation supervision;
- full dense generator replacement as the first response;
- full V19 end-to-end training before the v2 ancestry gate.
