## 2. Fixed scientific contracts

- Frozen current-source path: Clean-E14 / V18.
- Shared input: six historical Occ3D frames with mask_lidar observation.
- Canonical world: per-window t0 ego frame, with Z kept spatial.
- Static: historical-seen/t0-missing static + never-seen future static.
- Dormant: reliably observed historical source absent at t0.
- Birth: future dynamic identity with no reliably observed historical ancestor.
- Composition: V18 > Dormant > Birth > Static, protected add-only.
- Zero V20 contribution must equal V18 elementwise.
- Train/dev selection is scene-disjoint.
- Full 4369 evaluation is run only after structure and thresholds are frozen.

## 6. Stage 2 Static Repair v2

The original Stage-2 trainer `train_p0_f9_v20_static.py` is retained only to
reproduce the failed 2026-09-26 experiment.  It must not be used for new
scientific runs.  Its future-lidar-only supervision, all-one training query
channel, class/tile reweighting and canonical conflict deletion do not match
formal protected-add-only deployment.

The corrected protocol is `p0_f9_v20_static_repair_train_v2`:

- historical `mask_lidar` is still an input evidence mask;
- future `mask_lidar` is never a supervision-validity mask;
- supervision covers the same full future OCC grid as formal evaluation;
- frozen V18 defines the decision support: only V18-free voxels are supervised;
- static GT keeps its semantic label;
- free GT and dynamic GT both map to Static `free/no-add`;
- the query-mask input channel is the exact runtime `M_query`;
- every future voxel/horizon contributes independently, so conflicting labels
  that map to one canonical cell are not discarded;
- loss is ordinary per-future-voxel CE, without class weighting or equal-tile
  reweighting.

First build the causal V18-free support cache.  This cache contains no future
GT and no future lidar masks:

~~~bash
CUDA_VISIBLE_DEVICES=0 "$PY" -u \
  tools/real_motion/build_p0_f9_v20_static_repair_support.py \
  --stage1-cache "$V20_STAGE1_TRAIN" \
  --v18-cache "$TRAIN_V18" \
  --base-checkpoint "$CLEAN_CKPT" \
  --dataroot "$DATAROOT" \
  --info-pkl "$TRAIN_INFO" \
  --config "$RUNTIME_CONFIG" \
  --output-dir "$V20_STATIC_REPAIR_TRAIN" \
  --resume \
  --device cuda

CUDA_VISIBLE_DEVICES=0 "$PY" -u \
  tools/real_motion/build_p0_f9_v20_static_repair_support.py \
  --stage1-cache "$V20_STAGE1_DEV_SELECT" \
  --v18-cache "$V18_DEV512" \
  --base-checkpoint "$CLEAN_CKPT" \
  --dataroot "$DATAROOT" \
  --info-pkl "$VAL_INFO" \
  --config "$RUNTIME_CONFIG" \
  --output-dir "$V20_STATIC_REPAIR_DEV" \
  --resume \
  --device cuda
~~~

Before a full run, do a fixed small capacity check.  `--overfit-windows N`
uses the same first N train windows for train and validation and explicitly


`--max-windows` population is marked `diagnostic_only` and cannot enter
formal checkpoint selection or Stage-3 Dormant training.

The overfit gate is not based on CE alone.  Inspect the trainer's
`repair_diagnostics`: addition precision, static-positive recall and the
18x18 confusion must behave sensibly, with GT-free -> static errors included.
Then run the formal composed evaluator on the same checkpoint/population if
needed.  Do not start the full 20,430-window training if the fixed sample cannot
improve its composed V18+Static behavior.

### Static Repair speed benchmark

Training now uses an exact speed path while preserving the Repair-v2 objective
and optimizer-step semantics:

- train windows defer dense/addition/full-grid metrics to validation;
- repeated future-voxel CE terms that hit the same canonical
  `(query row, class)` are counted before log-softmax; loss and logits
  gradients are algebraically identical to repeated per-voxel CE;
- the history encoder and Static tile Conv3D path use channels-last-3D on CUDA;
- real tiles may be padded only along the batch dimension to a small multiple
  before Conv3D, then dummy outputs are cropped; no spatial tile geometry,
  GroupNorm statistics, or real-tile logits are changed;
- the Static final 1x1x1 convolution evaluates only the allowed Static/Free
  output rows instead of computing all 18 classes then selecting the same rows.

CUDA operator profiling on the pre-optimization path showed the dominant
backward cost came from repeated NLL/CE and tile Conv3D; grid-sample, CPU/cache,
geometry, H2D, and optimizer work were secondary.  The optimized path therefore
targets those measured hotspots rather than changing cache or query coverage.

Before a full epoch, profile a bounded formal-cache run:

~~~bash
CUDA_VISIBLE_DEVICES=0 "$PY" -u \
  tools/real_motion/train_p0_f9_v20_static_repair.py \
  --stage1-train-cache "$V20_STAGE1_TRAIN" \
  --stage1-val-cache "$V20_STAGE1_DEV_SELECT" \
  --repair-train-cache "$V20_STATIC_REPAIR_TRAIN" \
  --repair-val-cache "$V20_STATIC_REPAIR_DEV" \
  --v18-checkpoint "$CLEAN_CKPT" \
  --dataroot "$DATAROOT" \
  --train-info-pkl "$TRAIN_INFO" \
  --val-info-pkl "$VAL_INFO" \
  --output-dir "$ROOT/outputs/v20_static_repair_speed256" \
  --epochs 1 \
  --max-train-windows 256 \
  --max-val-windows 64 \
  --tile-batch-size 256 \
  --val-tile-batch-size 256 \
  --prep-workers 8 \
  --prefetch 32 \
  --progress-every 25 \
  --checkpoint-every-windows 0 \
  --profile-gpu-stages \
  --profile-warmup-windows 5 \
  --device cuda
~~~

The progress line reports wall throughput plus mean CUDA-event timing:

~~~text
rate=... win/s cpu_wait=... cpu_work=... tiles=.../win
gpu_ms=h2d:...,encoder:...,geometry:...,tile_decode:...,loss:...,backward:...,optim:...
~~~

The current active-tile geometry path is intentionally unchanged.  Use the
stage profile first; only optimize `q -> max_pool3d -> nonzero` if geometry
is a measured bottleneck, and keep an exact-equivalence test for any replacement.

### Cache-size note

The native Occ3D grid is `200 x 200 x 16 = 640,000` voxels per horizon.
Six horizons therefore contain 3.84 million voxel positions per window.
A single packed 1-bit six-horizon mask costs about 480,000 bytes/window before
container metadata. At 20,430 windows that alone is about 9.8 GB (decimal).

For this reason, do **not** cache dense `future_linear` for every training
window. It has 3.84 million indices/window: int32 would require about
15.36 MB/window (~314 GB decimal for 20,430 windows), and int64 about
30.72 MB/window (~628 GB). Cache compact transforms/tile metadata instead if
profiling later proves geometry to be a real bottleneck.

The Static Repair support cache intentionally stores a packed full-grid V18-free
mask because that avoids re-running frozen V18 every training epoch. Its index
already reports `packed_support_bytes`,
`mean_packed_support_bytes_per_window`, and
`v18_free_fraction_by_horizon`; inspect those before considering a new codec.
