1.1 12-step trajectory 不是“未来 6 个点”

严格复现官方 OccFM dataset：

6 history occupancy frames + 6 future occupancy frames → 对 12 个 frame 中的每一个 frame → 取 temporal info 里的 gt_ego_fut_trajs 的第一个 XY step → concatenate → [12, 2] → HIST_LAST=4，因此最前 6-4=2 rows 置零 → 输入 trajectory encoder (TRAJECTORY_LENGTH=12)

注意：第 12 个 trajectory row 对应最后一个 occupancy frame 自身的一步 future ego offset。虽然该 offset 超出 occupancy target 的最后时刻，它仍是官方 196 checkpoint 的 conditioning contract，因此 SWFM 为了 checkpoint/protocol 对齐也保留它。

2. 最终架构

Historical OCC + historical ego poses + allowed GT future ego protocol → Ego Compensation → Causal Real-Motion Decomposition ├─ confident-static → deterministic future-ego SE(3) transport └─ moving + uncertain → causal KTA → motion tube → sparse latent windows → prior-conditioned OccFM-Fut CFM (init 196) → Future WM-dynamic latent → Frozen VAE Decoder → Static-Protected Motion Composition

Free 是独立第四状态。KTA 只负责 causal motion prior / support，不作为最终 predictor。

4. Motion-window Sparse CFM

  • 50×50 latent grid 上选择固定 motion windows（默认 20×20），保留 OccFM Conv3d/U-Net/DiT checkpoint reuse。
  • generation support 才能创建 window；history context 只做 tie-break。
  • overlap windows 共享同一 global 50×50 initial noise canvas。
  • M_gen 外每一步 ODE clamp 到 exact E(empty)。
  • Static/KTA prior 使用 frozen VAE，按 OccFM rescale=10 后经 zero-init aligned prior projection 注入。
writable = dynamic_prediction AND write_support AND NOT confident_static

5. 正式训练前 P0

P0-0 — OccFM-Fut 196 Transition Equivalence

必须比较 official 50×50 / trajectory_length=12 与 modified 50×50 / zero prior / origin0。脚本还必须确认 traj_encoder.0.weight 从 196 成功加载；误传 199 会 fail。

P0-A

Frozen dense reference 改为 official OccFM-Fut 196，并使用同一个 [12,2] trajectory，比 Full / causal-static-only / moving+uncertain-only。

P0-B

用 future Moving arrival occupancy 测 causal reachability，同时报告 sparsity、window slot compute ratio 与 history connectivity。

P0-C

future Moving instance 的 t0 object occupancy 与 t0_confident_static_mask 求交；这里 box margin=0。

P0-D

Decomposition OracleSE3-static + all GT dynamic semantics
Causal-Support OracleSE3-static + GT dynamic semantics inside causal support

P0-E

A true-moving reconstruction；B actual WM-target reconstruction；C WM-target on sparse E(empty) canvas，并投影到 Moving-mIoU v2。

6. Frozen Moving-mIoU v2

  • GT world XY interval speed ≥ 0.5 m/s。
  • support = Box(t0→h) ∪ Box(th→h)，0.5m margin。
  • dynamic classes = 2,3,4,5,6,7,9,10。
  • 1s / 2s / 3s 先分别 class-mIoU，再对 horizon 平均。

Maneuver/KTA-hard 只改变 support 中的 GT instance，仍调用同一个 MovingMIoUV2MultiHorizon。

8. L40S 48GB

  • Sparse CFM BF16；Frozen VAE 默认 FP32。
  • TF32、cudNN benchmark、Flash/memory-efficient SDPA、fused AdamW。
  • shard-aware I/O、precomputed window plan、pinned/persistent loader。
  • tune_l40s.py 也强制 196 的 12-step traj_encoder 成功加载后才做性能扫描。
  • FP8 不进入主协议。

9. Fair Baseline Protocol

主表：SWFM (GT future ego, init OccFM-Fut 196) 对比 Official OccFM-Fut 196 以及其他获得同等 future ego information 的 baseline。199 hist-only 可以作为额外 information-ablation，但不能冒充同信息量主 baseline。
