1. 最终架构

Historical OCC + Historical Ego Poses → Ego Compensation → Causal Real-Motion Decomposition ├─ confident-static → SE(3) Transport → Future Static OCC └─ moving + uncertain → causal KTA → horizon-dependent motion tube → sparse latent windows → prior-conditioned OccFM CFM → Future WM-dynamic latent → Frozen VAE Decoder → Static-Protected Motion Composition

Free 是第四种独立状态，不能被 state==STATIC hard-freeze。默认 detector 使用 causal component-track hysteresis：明显移动→moving；低速且 persistence 高→confident-static；跟踪证据不足→uncertain。

WM target：Future dynamic-semantic GT inside causal generation support。
M_gen = causal(history, KTA) O_target^WM = DynamicSemantic(O_GT_future) ∩ M_gen Z_target^WM = E_frozen(O_target^WM)

因此不要再称训练 target 为 “true-moving-only future latent”；统一称 Future WM-dynamic latent。

3. Motion-window Sparse World Model

官方 OccFM transition 包含 Conv3d、temporal attention、U-Net down/up 与 DiT block。v1 为最大化 checkpoint 复用，在 50×50 latent grid 上只处理少量固定 motion windows（默认 20×20）。

  • generation_support 是 required future support，也是唯一能创建 window 的信号。
  • planning_support 只做相同 future coverage 下的 history/KTA context tie-break。
  • full latent cache 可预计算 window_origins/window_valid，正式训练不再每 step 跑 CPU planner。
  • 重叠 window 从同一个 global 50×50 noise canvas crop 初始噪声。
  • M_gen 外每一步 ODE 都 clamp 到 exact E(empty)。

3.1 Static/KTA prior

Static/KTA 与 state 使用同一个 frozen VAE，进入 adapter 前按官方 OccFM convention 乘 RESCALE_FACTOR=10；新增 prior projection zero-init，通过 spatially aligned AdaLN 注入。

3.2 Static-Protected Motion Composition

writable = WM predicts dynamic semantic AND write_support AND NOT confident_static

M_gen 控制计算范围，不是 wholesale overwrite mask。

4. Frozen Moving-mIoU v2

主 metric contract 冻结，不随结果调整。
  • protocol: interval_displacement_v2
  • GT world XY interval speed ≥ 0.5 m/s → Moving instance
  • evaluation support = Box(t0→h) ∪ Box(th→h)，两者均加 0.5 m margin
  • dynamic classes: 2,3,4,5,6,7,9,10
  • 1s / 2s / 3s 各自 class-mIoU，再对 horizon 算术平均

5. 正式训练前 P0

P0-A — Frozen causal real-motion decomposition

同一 frozen OccFM 比较 Full / causal-static-only / moving+uncertain-only。对应能力明显 collapse 时停止 sparse training。

P0-B — Arrival Coverage × Sparsity × History Connectivity

Generation reachability 用 future Moving arrival occupancy，不是 dual-box metric support。报告 BEV/latent coverage、support ratio、window slot compute ratio、history-connected future windows/cells。

P0-C — Actual Hard-Static Blind Spot

对 future Moving GT instance，在 t0 ego rasterize其真实 box，这里 margin=0，再与 t0 同类 semantic occupancy 相交，最后检查与 t0_confident_static_mask 的 overlap。报告 any / ≥50% / ≥80% hard-static instance ratio 和 voxel ratio。Moving-mIoU 的 0.5m margin 绝不能混入 P0-C。

P0-D — Two Oracle Bounds

Oracle组成含义
Decomposition OracleSE3-static + all GT dynamic semanticsdecomposition 理论上限
Causal-Support OracleSE3-static + GT dynamic semantics inside causal supportsupport/reachability 后上限

P0-E — Frozen VAE sanity

严格区分 metric target 与真实 WM target，报告三条主分支：A) true_moving_reconstruction：future_moving_occ；B) wm_target_reconstruction：future_dynamic_target_occ 在 causal support 内的 dynamic-semantic reconstruction；C) causal_sparse_wm_target_canvas：WM-target latent 在 M_gen 外 clamp 到 exact E(empty) 后的 reconstruction，并额外投影到 frozen Moving-mIoU v2。P0-E 不再把 future_moving_occ 当成 WM training target 的替代品。

8. NVIDIA L40S Runtime Profile

正式 profile 针对 L40S 48GB / Ada，但不引入会改变训练协议的 FP8-only 依赖。

模块默认原因
Sparse CFMBF16 autocastL40S Tensor Core 高吞吐；BF16 不需要 GradScaler
FP32 matmulTF32 + matmul precision high提升未 autocast 算子吞吐
Frozen OccFM VAEFP32保持 pretrained latent representation convention；只有 parity 通过后才开 VAE BF16
OptimizerCUDA fused AdamW减少 optimizer kernel overhead；不可用自动 fallback
DataLoaderpin + persistent workers + prefetch减少 H2D/input stall
DDPshard-aware sampler + gradient bucket view + static graph避免 cache shard thrashing 与额外 gradient copy
torch.compile默认关闭，可显式 benchmarkactive-window batch 动态，防止 graph-break/recompile 反而变慢

8.1 L40S batch tuning

python tools/real_motion/tune_l40s.py --cache data/latent_train --empty-latent data/empty_latent.pt --upstream-ckpt /path/to/occfm.ckpt --output outputs/l40s_batch_tune.json

默认扫描 4/6/8/10/12/16/20/24 samples/GPU，并记录 samples/s、transition windows/s、step latency、peak allocated/reserved VRAM；推荐结果保留至少 3GB memory headroom。最终 batch 必须写进 resolved config。

8.2 Cache path

Frozen VAE cache builder 支持 batched encode（L40S 默认 4）并预计算 window plan；sharded dataset 使用 shard-local / distributed shard-aware sampling，避免正式训练反复跨 shard torch.load。

10. YAML 与 Training

configs/real_motion_occfm.yaml 是唯一 runtime source-of-truth；每个 run 保存 resolved config。

10.1 Tiny

train_sparse.py 仅用于 64/128 overfit / small held-out。

10.2 Full

train_full.py 支持 single-GPU 或 DDP、distributed shard-aware training sampler、official-style split-decay AdamW、effective LR scaling、warmup+cosine、EMA=0.9999、resume、validation、best/last/periodic checkpoints，以及 L40S runtime profile。Validation 使用 exact no-padding distributed sampler：各 rank 不要求相同 val batch 数，因为 forward 直接运行 EMA module，不触发 DDP collectives；最终只 all-reduce真实样本加权的 numerator/denominator，从而避免 padding duplicate 对 best.pt 的偏差。

11. 最终执行顺序

pytest → official 50×50 transition equivalence → prepare smoke → P0-A → P0-B → P0-C → P0-D → P0-E → tiny latent cache → 64/128 overfit → small held-out → full latent cache + precomputed window plan → L40S batch/compile tuning → full training → overall / Moving / subset / Harm-Repair → L40S latency + GFLOPs
停止条件：transition equivalence、P0 或 tiny overfit 任一明显失败，先定位 motion/support、geometry/KTA、VAE、WM optimization 或 composition/evaluation；不要直接堆 Router/ABE/confidence loss。
