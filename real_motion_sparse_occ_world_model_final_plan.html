1. 最终架构

Historical OCC + Historical Ego Poses │ ├─ Ego Compensation（只用于 motion inference / KTA） │ └─ Causal Real-Motion Decomposition ├─ confident-static ── SE(3) Transport ── Future Static OCC └─ moving + uncertain │ ├─ Causal KTA ── Future Motion Tube ── Sparse Windows │ └─ Frozen VAE history / static / KTA latent │ Prior-conditioned OccFM CFM │ Future WM-dynamic latent │ Frozen VAE Decoder │ Static-Protected Motion Composition

Free 是独立状态，不允许通过 state==STATIC 被误 hard-freeze。默认 detector 使用 causal component-track hysteresis：明显移动→moving；低速且 persistence 高→confident-static；证据不足→uncertain。

2. 训练 Target 与 Metric Target 完全分开

最终训练 target：Future dynamic-semantic GT inside causal generation support，而不是“未来 GT 真正移动 instance”。
M_gen = causal(history, KTA) O_target^WM = DynamicSemantic(O_GT_future) ∩ M_gen Z_target^WM = E_frozen(O_target^WM)

因此一个历史 uncertain、未来恰好没超过 0.5 m/s 的车仍然是 WM 负责的对象，不会因为 Moving-mIoU 的 post-hoc threshold 而被监督成 empty。

3. Motion-window Sparse World Model

官方 OccFM transition 包含 Conv3d、U-Net down/up 和 DiT block，因此 v1 不强改成任意 packed-token Transformer，而是在 50×50 latent grid 上选少量固定窗口（默认 20×20）。论文措辞统一为 motion-guided sparse windows / motion blocks。

  • generation_support 是 required future support，唯一可创建 window 的信号。
  • planning_support 只在相同 future coverage 时用 history/KTA context tie-break。
  • 不同 window 不通信，因此不创建孤立 history-only window。
  • 重叠 window 从同一个 global 50×50 noise canvas crop 初始 z0。
  • M_gen 外每一步 ODE 都 clamp 到真实 E(empty)。

3.1 Prior conditioning

Static/KTA 与 state 来自同一个 frozen VAE，进入 prior adapter 前与官方 OccFM 一样使用 rescale factor 10；新增 prior projection zero-init，通过 spatially aligned token-wise AdaLN 注入，不用 global cross-attention。

3.2 Static-Protected Motion Composition

writable = WM predicts dynamic semantic AND write_support AND NOT confident_static

M_gen 控制“哪里计算”，不是 wholesale overwrite mask；confident-static 是硬保护。

4. Frozen Moving-mIoU v2

主 metric contract 冻结，不跟结果调整。
  • protocol: interval_displacement_v2
  • world XY interval speed ≥ 0.5 m/s → Moving instance
  • support = GT Box(t0→h) ∪ GT Box(th→h)，各加 0.5 m margin
  • 动态类固定：2,3,4,5,6,7,9,10
  • 1s / 2s / 3s 各自先算 class mIoU，再对三个 horizon 算术平均

旧位置负责惩罚 trailing ghost，新位置负责 missed arrival；future GT 只用于 metric/target/P0，不进入 causal support construction。

5. 正式训练前 P0

P0-A — Frozen Causal Real-Motion Decomposition（第一个方法实验）

同一个 frozen OccFM 比较 Full / causal-static-only / moving+uncertain-only。若对应 static/Moving 能力相对 Full 明显 collapse，不进入 moving-only sparse training。

P0-B — Arrival Coverage × Sparsity × History Connectivity

Generation reachability 使用 future Moving arrival occupancy，而不是 dual-box metric support。报告 BEV/latent coverage、active ratio、true-moving sparsity、window slot compute ratio，以及 future window 是否真正包含 historical motion evidence。

P0-C — Actual Hard-Static Blind Spot

对 future Moving GT instance，把 t0 GT box rasterize 到 t0 ego，并用 t0 semantic class 约束真实 occupied voxels，再与 t0_confident_static_mask 相交。主报告 any / ≥50% / ≥80% hard-static instance ratio 与 hard-static future-moving voxel ratio。历史 GT speed<0.5 只作为辅助统计；no-history/birth 解释 innovation 原因。

P0-D — Two Oracle Bounds

Oracle组成回答问题
Decomposition OracleSE3-static + all GT dynamic semantics分解本身理论上限
Causal-Support OracleSE3-static + GT dynamic semantics inside causal supportKTA/support reachability 后的上限

二者差值 = support/reachability loss；Causal-Support Oracle 与 learned WM 差值 = learning headroom。

P0-E — Frozen VAE Sanity

比较 full moving reconstruction、causal-support + E(empty) canvas 和 GT-support canvas。

6. 困难机动 / KTA-Hard 必须还是同一个 Moving-mIoU v2

旧的 per-instance intersection/union micro IoU 已废弃。新流程：

Calibration split -> freeze speed-change / turn-rate / KTA-error cuts Test split -> select GT instances by subset -> union each instance's ORIGINAL dual-box support @ 1s/2s/3s -> unchanged MovingMIoUV2MultiHorizon -> strict Moving-mIoU v2 on subset

因此可以严格报告 Uniform/Easy、Accel/Decel、Turning、Turning+Speed-Change、KTA-Easy/Medium/Hard 的 Moving-mIoU v2。KTA cuts 只在 calibration split 拟合，test 禁止重拟合。

7. Post-training Harm / Repair 与 Selector Headroom

最终 evaluator 同时报告：

  • voxel-level micro Repair/Harm
  • instance/tube-level macro Repair/Harm
  • Oracle KTA-vs-WM selector Moving-mIoU v2
  • Oracle selector headroom = Oracle − pure SWFM（pp）

只有 selector headroom 明显时才考虑 gate；优先 single-pass lightweight gate，CFG 最后。

9. YAML 与 Training Discipline

configs/real_motion_occfm.yaml 是唯一 runtime source-of-truth。核心脚本读取该 YAML、允许显式 CLI override，并保存 resolved config；Moving-mIoU frozen contract 会与代码常量互相校验。

9.1 Tiny/small

train_sparse.py 只用于 64/128 overfit 和 small held-out，不作为最终 full trainer。

9.2 Full

train_full.py 支持 DDP、official-style split-decay AdamW、effective LR scaling、1000-step warmup + cosine、EMA=0.9999、resume、validation 与 best/last/periodic checkpoint。默认 optimization 与官方 OccFM 发布设置对应，并由 YAML 统一控制。

10. 最终执行顺序

pytest -> Official 50×50 transition equivalence -> prepare smoke (16 windows) -> P0-A -> P0-B -> P0-C -> P0-D -> P0-E + profiler smoke -> tiny latent cache -> 64/128 tiny overfit -> small held-out -> full latent cache -> DDP full training -> overall / Moving / subset / Harm-Repair -> latency + GFLOPs
停止条件：transition equivalence、P0-A/B/C/D/E 或 tiny overfit 任一明显失败，都先定位 motion/support、geometry/KTA、VAE、WM optimization 或 composition/evaluation 层；不要直接堆 Router、ABE、repair/confidence loss。
